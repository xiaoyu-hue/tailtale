# 书时 TailTale 源码安全深度审计报告

- **审计版本**：v1.12.0（含 xmldom overrides 修复后）
- **审计日期**：2026-10-23
- **审计范围**：`src/platform/crypto/backup-crypto.ts`（备份加解密）、`src/modules/ai/service.ts`（BYOK 密钥存储 + EPUB 提取）、`src/modules/reader/ui/EpubReader.tsx` + `PdfReader.tsx`（EPUB/PDF 导入渲染）
- **方法论**：本环境 `zhongkui-skill` 的三层审查（静态清单 + 行为模拟 + 供应链溯源）移植到前端业务代码。其中 L1 静态规则对 65 个 `.ts/.tsx` 文件扫描（危险函数维度 `eval/new Function/子进程/动态执行` **0 命中**，证实代码基线无危险原语），本报告聚焦 L2/L3 对三大安全关键模块的语义级审查。
- **综合风险评级**：**低**。三大模块无高危代码级缺陷；唯一真实风险为供应链（xmldom via epubjs），已在同期通过 `npm overrides` 修复至 0.8.15。

## 一、备份加解密 `platform/crypto/backup-crypto.ts`

**裁定：实现正确，符合最佳实践，无高危缺陷。**

| 检查项 | 结论 | 证据 |
|---|---|---|
| 加密算法 | ✅ 合规 | AES-256-GCM（认证加密，自带完整性标签） |
| 密钥派生 | ✅ 强 | PBKDF2-HMAC-SHA256，迭代 600_000（OWASP 2025 对 SHA-256 的最小建议值） |
| 随机性 | ✅ 合规 | salt(16B) 与 IV(12B) 均由 `crypto.getRandomValues` 生成，每次加密独立 |
| 错误等价 | ✅ 抗侧信道 | 口令错误与密文篡改统一抛 `bad-password`，UI 文案合并，不泄露区分信息 |
| 输入校验 | ✅ 合规 | 解密时校验 `iterations` 为整数且 ≥1，否则 `corrupted` |
| 大文件处理 | ✅ 健壮 | base64 逐字节拼接，避免大备份 spread 触发调用栈上限 |
| 依赖面 | ✅ 最优 | 纯浏览器 WebCrypto，零第三方加密依赖（延续"能自己写不引依赖"原则） |
| 环境约束 | ✅ 明确 | 非安全上下文（无 `crypto.subtle`）显式抛 `unsupported` |

**残余风险与建议（均低优先级）**：
- WebCrypto 的 `CryptoKey` 由浏览器管理，JS 层无法显式清零；属平台固有限制，可接受。
- 600k 迭代在低端设备可能带来数百毫秒延迟，但安全优先，建议保留；如需优化可降为 OWASP 下限（≥600k 已是下限，无需再降）。
- 建议补充单元测试覆盖「错误口令 vs 篡改密文」均归为 `bad-password` 的等价性（当前单测已覆盖 `hash`/`events` 等，未覆盖此等价分支）。

## 二、BYOK 密钥存储与 EPUB 提取 `modules/ai/service.ts`

**裁定：密钥处理规范，EPUB 提取安全配置到位，无高危缺陷。**

### 2.1 BYOK（用户自带密钥）存储与传输

| 检查项 | 结论 | 证据 |
|---|---|---|
| 存储隔离 | ✅ 合规 | 仅存 `localStorage['tailtale:ai']`，明确"只随请求发往用户配置端点" |
| 传输安全 | ✅ 合规 | `isSecureEndpoint` 提前拦截非 https / 非本地回环端点，杜绝明文外发与混合内容 |
| 密钥不落日志 | ✅ 合规 | 模块注释明令"禁止打印密钥"；`Authorization: Bearer ${apiKey.trim()}` 仅入请求头，不进 URL/日志 |
| 无外传逻辑 | ✅ 合规 | 无上传/转发/遥测代码路径 |
| 串行队列 | ✅ 健壮 | AI 调用全部 `serialize` 排队，避免重复扣费与并发风暴 |

**残余风险**：`localStorage` 可被同源 XSS 读取。但项目全代码库无 `innerHTML`/`eval`/`new Function`（L1 扫描 0 命中），React JSX 默认转义，XSS 面近乎为零；且 BYOK 客户端模型下密钥本就在用户浏览器，这是该模式的固有信任边界，非缺陷。
**建议（可选）**：若追求更短暴露窗口，可改用 `sessionStorage`，但会丢失"跨会话保留配置"的体验，权衡后 `localStorage` 仍合理。

### 2.2 EPUB 文本提取

| 检查项 | 结论 | 证据 |
|---|---|---|
| 脚本执行禁用 | ✅ 关键防护 | `ePub(data, { allowScriptedContent: false, allowPopups: false })` |
| 内存峰值 | ✅ 合规 | 逐节 `load/unload` 懒加载，大书不占满内存 |
| 解析超时 | ✅ 健壮 | 25s `withTimeout` + `AbortController`，异常书降级引导转 TXT |
| 文本提取 | ✅ 安全 | `textContent` 提取，不执行章节内脚本 |

**供应链关联**：EPUB 解析经 epubjs → xmldom 处理不可信 XML，旧版 xmldom ≤0.7.x 存在 14 条 GHSA（XML 注入 + DoS）。**该风险已通过 `package.json` 的 `overrides` 强制 `@xmldom/xmldom` 至 0.8.15 闭环修复**（见本报告第四节）。

## 三、EPUB / PDF 导入渲染 `EpubReader.tsx` + `PdfReader.tsx`

**裁定：渲染层安全配置到位，无高危缺陷。**

### 3.1 EPUB 渲染（`EpubReader.tsx`）

| 检查项 | 结论 | 证据 |
|---|---|---|
| 脚本禁用（双重） | ✅ 合规 | 实例化与 rendition 两处均设 `allowScriptedContent: false` |
| 弹窗禁用 | ✅ 合规 | `allowPopups: false` |
| iframe 手势接管 | ✅ 体验/隔离 | 原生 `touchAction='none'` + 捕获阶段 `stopImmediatePropagation`，避免内置滑动与统一手势双翻页 |
| 非法 CFI 兜底 | ✅ 健壮 | `Promise.resolve(rendition.display()).catch` 回首页，防 unhandled rejection 卡死 |

**说明**：epub.js 在 iframe 渲染 EPUB 的 HTML/CSS。`allowScriptedContent:false` 已禁用 `<script>` 执行，恶意样式/CSS 不会造成脚本执行类危害；这是该渲染方案的标准安全配置，已正确应用。

### 3.2 PDF 渲染（`PdfReader.tsx`）

| 检查项 | 结论 | 证据 |
|---|---|---|
| 解析方式 | ✅ 安全 | `pdfjs.getDocument({ data })`，纯 canvas 渲染 |
| 脚本执行 | ✅ 合规 | pdf.js 不执行 PDF 内嵌 JS，渲染产物为位图 |
| worker 隔离 | ✅ 合规 | worker 独立加载（`pdf.worker.min.mjs`），主线程不阻塞 |
| 资源释放 | ✅ 健壮 | 卸载时 `doc.destroy()`，避免 PDF 大对象泄漏 |

**说明**：pdfjs-dist 4.x 版本较新；PDF 渲染路径不执行页面脚本，无脚本注入面。

## 四、供应链溯源（L3）与修复闭环

| 依赖 | 风险 | 状态 |
|---|---|---|
| `@xmldom/xmldom`（epubjs 传递依赖） | 高危：14 条 GHSA（XML 注入 + DoS），直击 EPUB 导入不可信输入路径 | **已修复**：`package.json` 加 `overrides` 强制 `^0.8.12`，实际安装 0.8.15，`npm audit` 高危项清零 |
| `esbuild` / `vite`（传递依赖） | 中：本地 dev server 可被恶意网站读取响应 | **缓建**：仅影响 `npm run dev` 本地环境，不触及 `dist` 产物与线上部署；修复需升 vite@8（breaking），收益低 |
| `epubjs` 0.3.93 | 发布停滞于 2022，但为当前维护主线（0.4.x 是 2018 老分支，npm audit 建议的"升级 0.4.2"实为降级陷阱，已识别规避） | 维持 0.3.93 + xmldom overrides |

**关键发现**：`npm audit` 建议"升级 epubjs 到 0.4.2"是**陷阱**——0.4.2 依赖更老的 `xmldom@0.1.x` 线，而 0.3.93 把 xmldom 锁死在 `0.7.x`，永远装不到修复版；真正解法是 `overrides` 强制 xmldom 升级，零 breaking。

## 五、综合结论与后续

**风险评级：低。** 三大安全关键模块代码实现正确、配置到位，无高危代码级缺陷；唯一真实风险（xmldom 供应链）已闭环修复。

**遗留项（低优先级，需人工/网页端动作）**：
1. **Dependabot security updates 开关**：经 GitHub API 开启时返回 404，根因为所用 token 缺少 `security_events` scope；`secret_scanning` 与 `push_protection` 已确认处于 enabled 状态。建议用户在仓库 **Settings → Code security** 手动开启 "Dependabot version updates / security updates"，或提供带 `security_events` scope 的 token 由工具开启。
2. **CodeQL**：已通过 `.github/workflows/codeql.yml`（workflow 方式，pin SHA）落地，push 后自动在 Security 标签页产出扫描结果，无需额外 scope。
3. **esbuild/vite** 中危漏洞：仅本地 dev 受影响，建议缓建，待生态成熟或下次大版本时处理。

**审计员注**：本审计基于静态代码审查与依赖溯源，不替代运行时渗透测试；零日漏洞与加密混淆载荷不在静态审查覆盖范围内。
