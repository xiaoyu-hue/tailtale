| 前端框架 | React 18 + Vite | 与核心开源积木同技术栈，二创成本最低；生态最大 |

## 2. 架构总览

```
浏览器（React + Vite + PWA）
 ├─ 阅读引擎：epub.js / pdf.js（本地解析，书不出浏览器）
 ├─ 游戏逻辑：打卡/XP（reading.js）+ 宠物逻辑（本地存储）
 ├─ AI：fetch 直连 DeepSeek（用户自带密钥）
 └─ 数据：localStorage / IndexedDB

托管：Cloudflare Pages ← GitHub 推送自动部署；CI 用 GitHub Actions 做类型检查 / 测试 / 构建门禁（提供质量可见性，不阻止 Pages 发布——真正阻止发布需将 Pages 改为「从 CI 构建产物发布」）
```

## 3. 各层选型说明

### 3.1 前端：React 18 + Vite + PWA

- 与两个核心开源积木（MindSpace 阅读逻辑、kit 工具箱）同为 React 技术栈，代码可直接复用
- Vite 构建速度快，配置简单
- vite-plugin-pwa 提供 Service Worker 离线缓存与安装能力

### 3.2 电子书渲染：epub.js / pdf.js

- epub.js：BSD-2-Clause（Copyright (c) 2013, FuturePress），浏览器 EPUB 解析与渲染，支持分页/滚动、主题、进度定位（CFI）；1.1.0 实际引入时核实随包 license 文件，更正此前规划文档的 MIT 误记
- pdf.js：Apache-2.0，PDF 渲染；1.1.0 引入，canvas 按页渲染
- foliate-js（MIT）作为备选，支持 EPUB/MOBI/AZW3/FB2/CBZ 更多格式
- Web 环境下渲染引擎直接运行于页面，无容器限制

### 3.3 AI 接入：BYOK 浏览器直连

**实测记录（2026-10-20）**：向 `api.deepseek.com` 发送携带 Origin 头的请求，响应返回 `access-control-allow-origin`（回显来源）与 `access-control-allow-credentials: true`，确认支持浏览器跨域直连。

设计要点：

- 用户密钥仅存浏览器 localStorage，代码中禁止上传或传输至任何服务器
- 设置页提供 DeepSeek 预设与自定义 OpenAI 兼容端点（base_url / api_key / model），后者可覆盖所有 OpenAI 兼容大模型
- 调用前弹窗预估费用，防误触；不设服务端限额（密钥归用户，成本自担）
- 备用方案：若个别模型端点不支持 CORS，使用 Cloudflare Worker 做转发代理（密钥只过路不存储）

### 3.4 存储：localStorage / IndexedDB

- 全部数据本地存储，无账号系统
- IndexedDB 用于较大数据（如书摘、书籍元信息），localStorage 用于配置与轻量状态
- 提供 JSON 导出/导入作为备份手段
- 内置公版书（1.9.0）：书籍文本随应用同源分发（public/library-books/），用户点「领取」时读取并经 hashText 指纹校验后写入 IndexedDB，与导入的书同一张表；SW 不缓存书籍文本（workbox.globPatterns 排除），备份导出不含内置书内容

### 3.5 备份加密：浏览器 WebCrypto（1.11.0）

- 备份导出三档：标准（默认，剔除 AI 密钥）/ 加密（整文件加密）/ 完整明文（含密钥，导出前警示）；加密档默认不开启，用户显式选择
- 算法：PBKDF2-HMAC-SHA256（60 万次迭代，OWASP 2025 建议值）派生密钥 + AES-256-GCM 加密；浏览器原生 WebCrypto 实现，零第三方依赖（延续「能自己写的绝不引依赖」）
- GCM 认证标签使「口令错误 / 文件被篡改」以同一失败呈现（安全上不区分）；口令只用于本次派生、不落任何存储，无找回后门
- 加密信封（app / encrypted / kdf / cipher / ciphertext）与明文备份同为 .json，导入时按字段自动识别并弹口令框；解密内容仍过一次 parseBackupBundle 形状校验，防伪造内容注入
- 代码位置：`src/platform/crypto/backup-crypto.ts`（原语）+ `settings/model.ts`（信封纯函数）+ `settings/service.ts`（编排）；单测覆盖往返 / 错口令 / 篡改 / 损坏 / 信封校验
- 边界：客户端加密防不了恶意软件与被篡改的程序本身；WebCrypto 需安全上下文（HTTPS），非 HTTPS 环境加密档禁用；忘记口令 = 备份永久无法恢复（产品文案明示）

### 3.6 托管与 CI：Cloudflare Pages + GitHub Actions

- Pages 连接 GitHub 仓库，推送自动构建发布
- 免费额度对个人静态项目充足（静态请求不计费）
- 部署策略（与 PRD 第 9 节一致）：当前主站为 `*.pages.dev` 二级域名 https://tailtale-520.pages.dev/（`main` 分支推送自动构建发布，暂定位主站）；自定义域名与公开上架待产品进一步立得住后再启动

## 5. 已知约束

| 约束 | 影响 | 应对 |
|---|---|---|
| Cloudflare 在中国大陆无节点 | 国内移动网络访问 *.pages.dev 不稳定 | 试水期可接受；正式国内访问需域名 + ICP 备案 + EdgeOne CDN |
| ICP 备案要求申请人年满 18 周岁 | 开发者当前无法单独备案 | 监护人代办，或后置至成年后处理 |
| iOS PWA 限制 | 无推送通知；本地文件可能被系统清理 | 核心数据提供 JSON 备份；重要功能不依赖推送 |
| 移动浏览器文件持久化 | 用户本地导入的书在部分移动浏览器无法长期驻留 | 引导使用内置公版书库；导入功能标注为实验特性 |

## 6. 备用方案

| 场景 | 方案 |
|---|---|
| 个别模型端点不支持 CORS | Cloudflare Worker 五代码转发代理 |
| 需要进度云同步 | Cloudflare Workers + KV/D1，前端不变 |
| 国内正式访问 | 域名 + ICP 备案 + 腾讯云 EdgeOne Pages/CDN |
| 需要服务端渲染 | 评估 Next.js 迁移（当前无此需求） |
